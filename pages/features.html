Primary feature table

Live scoring schema

The dashboard exposes the fields below directly, while the remaining pipeline attributes are filled in automatically to keep the request structure consistent.

Attribute name Type Description
vehicle_segment categorical Vehicle class focus such as crossover, sedan, pickup, or EV-oriented segments.
shopper_intent_decile numeric Intent band from 1 to 10. Higher values indicate stronger active shopping behavior.
powertrain_focus categorical Primary propulsion preference such as ICE, hybrid, PHEV, or BEV.
days_since_last_brand_engagement numeric Recency of the latest digital or dealer interaction with the brand.
intent_engagement_score numeric Composite engagement score representing lead quality across multiple touchpoints.
market_region_tier categorical Market context such as major metro, suburban, or smaller regional zones.
competitive_conquest_intensity_band categorical Competitive market pressure faced by the targeted nameplate or segment.
days_supply_inventory_proxy_band categorical Supply availability signal that helps separate constrained and balanced markets.

Locked defaults

These fields are applied automatically so every prediction request remains aligned with the training pipeline.

model_year_position: Current Model Year primary_channel: Paid Social secondary_channel_syndicated_flag: No nameplate_lifecycle_stage: Steady State dealer_cosponsored_local_campaign_flag: No credit_availability_consumer_stress_band: Benign

Why this matters

Schema parity Keeps production requests shaped like the data used to train the classifier.
Fewer runtime errors Prevents missing-field problems when users only enter the core lead signals.
Cleaner demos Business users can focus on the handful of inputs they actually control.
